Per abilitare il debug o la profilazione, copia il file `DEBUG_template.toml` in `DEBUG.toml` e modificalo.

## Come creare uno script bash per il debug offline dalla console

1. In `DEBUG.toml`, imposta `create_bash_script = true`.
2. Esegui l'estensione `inkstitch.py` da Inkscape per creare uno script bash con il nome specificato in `bash_file_base` in `DEBUG.toml`.
3. Esegui lo script bash dalla console.

## Abilitare il debug

1. Imposta `debug_type` su uno dei seguenti valori: - vscode, pycharm, pydev. Consulta i dettagli qui sotto.

   * `debug_type = vscode`: utilizza `debugpy` per l'editor vscode.
   * `debug_type = pycharm`: utilizza `pydevd-pycharm` per l'editor pycharm.
   * `debug_type = pydev`: utilizza `pydevd` per l'editor eclipse.

2. Imposta `debug_enable = true` in `DEBUG.toml`.
   oppure utilizza l'argomento della riga di comando `-d` nello script bash.
   oppure imposta la variabile d'ambiente `INKSTITCH_DEBUG_ENABLE = True` (o 1 o yes o y).

## Abilitare la profilazione

1. Imposta `profiler_type` su uno dei seguenti valori: - cprofile, profile, pyinstrument, monkeytype.

   * `profiler_type = cprofile`: utilizza il profiler `cProfile`.
   * `profiler_type = profile`: utilizza il profiler `profile`.
   * `profiler_type = pyinstrument`: utilizza il profiler `pyinstrument`.
   * `profiler_type = monkeytype`: utilizza il profiler `monkeytype`.

2. Imposta `profile_enable = true` in `DEBUG.toml`.
   oppure utilizza l'argomento della riga di comando `-p` nello script bash.
   oppure imposta la variabile d'ambiente `INKSTITCH_PROFILE_ENABLE = True` (o 1 o yes o y).

## Note aggiuntive

- Per disabilitare il debugger durante l'esecuzione da Inkscape, imposta `disable_from_inkscape = true` in `DEBUG.toml`.
- Per modificare i nomi dei vari file di output, consulta `DEBUG.toml`.
- Per evitare che il debugger attenda la connessione (editor vscode), imposta `wait_attach = false` in `DEBUG.toml`.
- Per preferire la versione di Inkex inclusa in Inkscape rispetto alla versione installata tramite pip, imposta `prefer_pip_inkex = false` in `DEBUG.toml`.

## Come eseguire il debug con...

### LiClipse

1. Installa [LiClipse](https://liclipse.com) (non è necessario installare Eclipse per prima).
2. Avvia il server di debug come descritto qui: <http://www.pydev.org/manual_adv_remote_debugger.html>
   * Segui la "Nota:" per abilitare l'elemento del menu del server di debug.
3. Copia e modifica un file chiamato `DEBUG.toml` da `DEBUG_template.toml` accanto a `inkstitch.py` nella tua directory clonata dal repository Git.
   e imposta `debug_type = pydev`.
4. Esegui qualsiasi estensione e PyDev avvierà il debug.

### PyCharm

È necessario utilizzare la versione Professional di PyCharm e non la versione Community.
Jetbrains ha scelto di rendere il debug remoto una funzionalità Pro.
Per eseguire il debug delle estensioni Python di Inkscape, il codice dell'estensione e Inkscape funzionano in modo indipendente da PyCharm e comunicano solo con il debugger tramite una socket TCP. Pertanto, il debug è "remoto", anche se si trova sulla stessa macchina, connesso tramite l'interfaccia di loopback.

1. `pip install pydev_pycharm`

   `pydev_pycharm` viene aggiornato frequentemente. Jetbrains suggerisce di installare
   una versione compatibile con la build corrente. Ad esempio, se la tua
   build di PyCharm, come indicato nel menu PyCharm -> Informazioni su PyCharm, è 223.8617.48,
   potresti eseguire:

   `pip install pydevd-pycharm~=223.8617.48`

2. Dal menu "Run" di Pycharm, scegli "Modifica configurazione..." e crea una nuova
   configurazione. Imposta "Nome host IDE:" su `localhost` e "Porta:" su `5678`.
   Puoi lasciare le impostazioni predefinite per tutte le altre opzioni.

3. Crea un file chiamato `DEBUG.toml` nella directory principale del tuo repository Git, come descritto in precedenza.
   Imposta `debug_type = pycharm`.

4. Crea un collegamento simbolico nella directory delle estensioni di Inkscape alla
   directory principale del tuo repository Git. Su un Mac, ad esempio:

   ```
   cd ~/Library/Application\ Support/org.inkscape.Inkscape/config/inkscape/extensions/
   ln -s <percorso completo alla directory principale del tuo repository Git di Ink/Stitch>
   ```

   Su altre architetture, potrebbe essere:
   ```
   cd ~/.config/inkscape/extensions
   ln -s <percorso completo alla directory principale del tuo repository Git di Ink/Stitch>
   ```

   Elimina eventuali altri file di Ink/Stitch o riferimenti a Ink/Stitch dalla
   directory delle estensioni, altrimenti vedrai voci duplicate nel menu delle
   estensioni di Ink/Stitch in Inkscape. In alternativa, puoi utilizzare la [configurazione multiversione](/developers/inkstitch/multiversion/).

5. In Pycharm, fai clic sull'icona "debug" (a forma di insetto) nell'angolo
   in alto a destra o premi Ctrl-D per avviare il debug. Il pannello del debugger di PyCharm
   mostrerà il messaggio "In attesa della connessione al processo...".

6. Esegui un'azione in Inkscape che invoca il codice dell'estensione Ink/Stitch e
   il debugger verrà attivato. Se hai lasciato la casella "Sospendi dopo la connessione"
   spuntata nella configurazione di esecuzione, PyCharm si fermerà all'istruzione `self.log("Debugger PyDev abilitato.")`,
   sotto. Deseleziona la casella per consentire l'esecuzione automatica fino al tuo primo punto di interruzione.

### VS Code

Consulta:
* <https://code.visualstudio.com/docs/python/debugging#_command-line-debugging>
* <https://code.visualstudio.com/docs/python/debugging#_debugging-by-attaching-over-a-network-connection>

1. Installa l'estensione Python per VS Code.

   `pip install debugpy`

2. Crea un file `.vscode/launch.json` contenente:

   ```
   "configurations": [ ...
        {
           "name": "Python: Attacca",
           "type": "python",
           "request": "attach",
           "connect": {
               "host": "localhost",
               "port": 5678
            }
        }
     ]
     ```

3. Crea un file chiamato `DEBUG.toml` nella directory principale del tuo repository Git, come descritto in precedenza.
   Imposta `debug_type = vscode`.

4. Avvia il server di debug in VS Code facendo clic sull'icona di debug nel pannello
   a sinistra, seleziona "Python: Attacca" dal menu a discesa e fai clic sulla freccia verde.
   Il server di debug verrà avviato e si connetterà ai processi Python in esecuzione,
   ma si chiuderà immediatamente se non sono in esecuzione processi Python.

## Profiler

### Profiler

Abilita la profilazione come descritto in precedenza utilizzando `profile`.
Ink/Stitch verrà eseguito sotto un profiler e il risultato verrà salvato in `profile_stats`.
Questo ti dirà quali funzioni impiegano quanto tempo per essere eseguite.

Installa snakeviz con `pip install snakeviz`.

Apri le statistiche con `snakeviz profile_stats.prof`.
Questo visualizzerà un grafico interattivo utile nel tuo browser.

### Monkeytype

Gran parte del nostro codice, in particolare il codice più vecchio, non dispone di annotazioni di tipo.

Se desideri aggiungere annotazioni di tipo al codice più vecchio o scoprire quali tipi vengono utilizzati in una parte del codice senza annotazioni di tipo, potresti trovare [MonkeyType](https://monkeytype.readthedocs.io/en/stable/) utile.

* Imposta `profile_enable = True`.
* Rimuovi il commento dalla riga `profiler_type = "monkeytype"`.
* Installa monkeytype con `pip install monkeytype`.

Dopo aver eseguito il comando Ink/Stitch, verrà visualizzata una finestra che ti indica come eseguire Monkeytype e utilizzare le informazioni sui tipi raccolte.
Esecuzioni di comando multiple contribuiranno tutti al database delle informazioni sui tipi.
